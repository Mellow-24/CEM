# `@deepseek-ai/dsh-client-ui-voice`

[English](README.md) | 中文

显式 `html[data-dsh-mobile]` 入口使用同一会话语音配置及通话生命周期。移动字幕宽度包含内边距，语音状态文本在输入栏内换行；桌面几何布局保持不变。

移动端欢迎语、通话句子和已提交消息的音频通过携带页面认证信息的同源 fetch 下载，再使用本地 Blob URL 播放。每个移动运行时在欢迎语及后续回答中复用同一个经用户手势解锁的媒体元素；解锁用的静音不会推进通话状态。预读不会改变当前播放源。停止或取消会释放各自请求和 Blob URL，不会停止其他句子。下载、HTTP 授权、无效音频和播放失败分别提供诊断提示。桌面播放保留直接音频 URL 的渐进式加载。此方式不会绕过浏览器的证书信任或音频权限。

通过 [`@deepseek-ai/dsh-speech-web`](../../speech/speech-web/README.md) 提供浏览器麦克风输入和已提交 assistant 回复的语音控件。Node 端是空 roster plugin。浏览器端在 `conversation.input.right` 注册麦克风，在 `conversation.composer.dock` 注册短暂状态，并在 `conversation.chat.assistant-actions` 注册播放或停止操作。

只有 `voiceClient.profile(sessionId)` 报告当前 Session 的 live Agent scope 已授权操作时，全局 client plugin 才渲染对应控件。它不从 agent-preset id 推断能力。连接重置会刷新已缓存 profile；离开 Session 会停止麦克风 track、转写、合成准备和媒体播放。

面向客户的外壳可以请求 `ctx.voiceRuntime.create(session)`，在相同录音和通话控制器之上呈现自己的视觉控件。该客户端服务通过 Cordis 注入完成跨插件协作。返回的运行时归属一个 Session，界面卸载时必须释放；它与标准 slot 沿用同一组 Host profile、麦克风生命周期、通话打断、字幕时序和清理行为。

麦克风捕获会从 Host 接受且浏览器 `MediaRecorder` 支持的类型中选择第一个，并上传一个完整 Blob。识别文本经去除首尾空白后，在新行追加到现有草稿。它仍可编辑，也不会自动提交。

转写后，只要草稿与控件写入的文本逐字节相同，且 Host profile 也允许合成，麦克风就会变为“语音发送”。语音发送会在调用普通输入提交操作前，同步为 Session arm 一条新的已提交 assistant 消息。Arm 时已提交 assistant 的最大 seq 构成边界，因此重新挂载或稍后分页加载的历史不能 claim 该 arm。只有转写能力的 profile 显示“发送转写”，并在不 arm 的情况下提交。普通“发送”永远不会 arm 播放；编辑草稿会让控件恢复麦克风模式。

最终 assistant 操作会原子 claim 一条已 arm 的消息，并通过 `sessionId`、`messageId` 和 Host 授权 profile 请求合成。所有播放文案都会把结果标明为 AI 合成语音。桌面播放直接使用返回的同源 URL，因此分块音频响应可以在完成前开始播放。移动播放等待完整响应，受 Host 合成输出大小限制。语音发送会尝试解锁用户手势播放，但自动播放被拒绝仍是普通播放错误，同一消息会保留显式重试按钮。每条具有合成能力的已提交 assistant 消息仍可手动播放和停止。

## 语音通话

`VoiceCallView.messages` 为当前通话保留带稳定 id 的欢迎语、识别草稿及生成回答。打断只标记当前回答，不删除文字；静音或放弃的草稿标记为未提交。开始另一通电话时重置这份临时记录。它不是第二份模型历史：已接受消息仍在普通 Session 中，欢迎语不产生持久化的助手事件。

自动打断在本次回答的生成、合成准备、播放和句间等待期间持续筛选识别内容。空文字、单字及独立附和不打断；单独的“停”也不是停止命令。明确停止使用本地规则，临时识别须等待 `confirmationMs`。Host 启用 `interruption.semantic` 时，其他完整候选结合近期用户问题及实际开始播报的句子进行分类，期间播放继续。只有肯定判断才能取消本次回答。超时、提供方失败、静音、更新的识别文字、另一轮回答及挂断都不能授权过期打断。未配置语义判断时，识别完成且明确指向客服的纠正及澄清句式使用本地规则。未接纳候选不进入字幕及普通历史。播放先于识别完成时，候选仍保留筛选状态。没有本次回答的收听状态接受普通提问。已接纳相邻片段共用 `utteranceMergeMs`，分类耗时计入该间隔；确认续说按顺序包含原问题和新片段，不改写历史。

单独识别到的停止命令会取消本次回答并清空排队问题，不发起新的模型请求。停止后紧跟问题的复合句沿用正常续接提交。其他外壳可以调用 `setMuted(boolean)`，丢弃未完成的识别并停止发送麦克风音频帧；取消静音后，收到新的语音开始事件才接受识别结果。已经上传的音频无法撤回。`interrupt()` 取消本次回答和播放，但不切断识别连接。在没有活动识别循环时，这两个操作不产生作用；原有通话控件及 Host VAD 默认值保持不变。

Host 公布流式识别、合成和 `call` 配置时，输入框提供全屏通话。固定欢迎语结束后，麦克风持续发送单声道 16 kHz PCM16 音频帧，助手回答期间也保持收音。服务端返回实时字幕、检测开口并在停顿后完成片段。用户字幕保留已完成片段，并在其后追加当前临时识别结果；在 `utteranceMergeMs` 内继续说话会取消待提交操作，使累计的完整文字作为一条用户消息进入普通 Session。客服正在播报时，只有确认用户要占用话轮才会停止播报并取消尚未完成的回答；单纯开口、可能的回声及被动附和不会打断。选定的固定欢迎语在通话前预加载，点击时直接播放，并行准备麦克风。自动语言模式默认使用配置的粤语欢迎语；识别文字随后进入普通 Session 的回复语言策略。手动选择语言时使用该语言的预制欢迎语。欢迎语不产生模型请求或会话消息，识别事件不会打断它；结束前采集的麦克风帧在本地丢弃，但挂断和服务错误仍会停止播放。请在欢迎语结束后提问，其间说话不会转写。用户转写和客服播报使用带标识的独立气泡；Session 投影更新时，已生成的助手文字立即显示，不依赖音频开始，因此提供方延迟或失败不会令通话界面空白。通话音频按 Host 的 `playbackRate` 播放并保持音调。通话无需发送按钮。

提交的消息立即通过普通会话日志持久化。关闭弹窗不会复制或重写历史。挂断、切换 Session、更改预设和连接重置会停止录音与播放，并取消通话尚未完成的轮次。其他用户消息进入会话时，通话结束，但不会取消该用户的工作。通话要求普通 Session 空闲且队列为空。识别、麦克风和通话传输错误会停止循环。欢迎语结束后，单句合成或播放失败只会停止当前回答剩余的音频并显示提示，随后恢复收音，不会关闭识别连接。未完成的回答受 Host 配置的等待时限约束。

麦克风访问需要安全浏览器环境。Qwen 识别服务负责语句检测；浏览器在识别前采用 Host 的 `microphone` 处理选项，使用 `responseTimeoutMs` 限制回答等待时间，并使用 `maxPendingAudioMs` 约束麦克风上行积压。采集每 100 毫秒产生一帧。每次只允许一个音频上传请求在途；等待期间采集的帧合并为后续有序上传，不额外计时攒批，也不丢弃采样。每次请求最多携带 64,000 字节（两秒），排队与在途 PCM 则可覆盖单独配置的积压时长。这样短暂传输抖动或主线程暂停可以自行恢复，同时不会产生超大请求。超过总积压时长会结束通话，避免无限重放过期录音。

通话按句子从实时助手文本中提取播报内容，出现适合朗读的标点后立即合成。句末标点必定提交片段；逗号、顿号等停顿标点仅在片段达到 `sentencePauseMinChars` 后提交，避免产生过短的独立请求。排版换行不会结束一句话。不含字母或数字的片段（例如回答末尾单独出现的 emoji）保留在文字历史中，但不发起语音合成。当前句开始产生可听声音后，队列会在保持播放顺序的同时最多准备下一句；当前音频尚未证明可用时，不会发起推测性预读。Host 公布降级合成 profile 时，首选提供方在音频开始前失败会令当前句重试一次，并在本次通话后续播报中沿用成功的降级 profile。内部合成分段沿用原文空白，不额外产生字幕换行。无标点的长句按 `sentenceMaxChars` 截断，队列受 `sentenceQueueLimit` 限制。打断或挂断会停止当前音频与排队内容。Host 校验日志中的文本前缀，拒绝过期内容与推理块。已听到的内容不能撤回，历史也不表示实际播放进度。

## Model Experience

通过 `ui-conversation` 负责的普通问题提交，以及 `speech-web` 负责的可选已记录打断分类间接影响模型；后者接收近期问题、实际播报文字及候选语句，不回答用户或改变回答语言。

#### KV Cache effect

展示和播放不增加模型 token。提交的转写追加普通用户消息，续说会重复原问题。语义分类仅为经过筛选的插话候选增加有上限的辅助输入及输出 token，不改变对话模型历史或缓存前缀。

## Known Limitations and Deferred Work

- **说话人身份及保守接纳** — 文字分类无法验证说话人身份。旁人说出相关问题或有效命令仍可能打断；不确定或超时的自然插话可能被忽略。仍需浏览器音频处理及粤语、英语设备测试。
- **移动端起播延迟** — 通话逐句完整下载后播放，不等待整段回答。与桌面渐进式播放相比，首次出声可能稍慢；下一句的预读仍与当前音频播放重叠。
- **仅在 Session idle 时语音发送** — 较早的 turn 运行时，录音和语音发送保持禁用，因为 input action 不提供 prompt 到 turn 的回执；接受排队语音输入可能让较早 turn 的已提交回复 claim 该 arm。
- **完整录音转写** — MediaRecorder 字节只在“停止”后才跨越 Host；不支持局部识别和可安全中断后恢复的上传。
- **仅当前 Session 播放** — 切换 Session 会停止音频，而不会让它在后台继续播放。
