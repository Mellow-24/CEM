# Agent Note: CEM customer conversation portal

Status: implemented

English | [中文](2026-09-12-cem-customer-conversation-portal.zh.md)

## Problem

The Macau customer-service presets and operations console run inside a general agent interface whose navigation, developer controls, and product identity are inappropriate for a public customer entry point. A disconnected visual prototype would look correct but could not demonstrate real Session continuity, streaming answers, cancellation, or speech transcription.

## Decision

`@deepseek-ai/dsh-client-ui-customer-portal` owns a customer-facing CEM shell at `/customer`. Its client plugin registers an alternate `root` occupant only when that pathname is active. The standard root remains the only occupant at `/`, so the existing operator interface and administration workflow retain their current behavior and URL.

The customer shell reuses the existing Session runtime and API connection. It uses the current blank Session or connects a blank Session through the current Workspace, then selects `macau-customer-service` before the first prompt. The route always reaches the customer greeting and grouped recommended questions before a new turn. Its fixed-height history rail derives recent non-blank root Sessions from the shared Session list, excludes ids in the Workspace archive set, admits only the same customer-service preset, and renders at most eight entries per page. It opens the selected canonical Session instead of copying messages into portal state. A confirmed customer delete calls the existing Workspace archive operation: the entry disappears from customer history while its durable log remains available for quality inspection; running entries do not offer that operation. User prompts, cancellations, durable history, partial assistant text, and final answers follow the same Host paths as the standard conversation interface. The customer projection shows user prompts and customer-facing answer prose. A finalized assistant step containing a tool call stays hidden, as does first-step partial text that could otherwise flash before the call arrives; later answer-stage partial text remains visible, and a direct first-step answer appears after completion. Tool, lookup-announcement, and reasoning records remain available in the canonical Session log and the [administration console](2026-09-04-customer-service-admin-console.md).

The initial customer state uses CEM visual identity, a greeting, and grouped Traditional Chinese questions whose subjects have approved entries in the deployed Macau knowledge corpus. `dsh-client-ui-voice` provides a Cordis client service over its existing Session-scoped recording and [voice-call controllers](2026-09-03-customer-service-voice-calls.md). The portal requests one runtime from that service for its active Session: the composer microphone records and transcribes a reviewed utterance, while the header call button presents continuous recognition, interruption, prepared greeting playback, synchronized captions, and sentence synthesis. Both modes use the preset-authorized Host profiles and dispose their media when the customer Session leaves the page.

The Web bundle declares the DashScope conversation provider's Qwen thinking dialect and explicitly selects its `off` reasoning effort. Tool selection and the answer stage therefore stream without provider-default hidden reasoning. The RAG query embedding, candidate count, vector threshold, reranking request, rerank threshold, and final result ordering remain unchanged; the latency choice does not replace or weaken knowledge retrieval.

The [Shenyi Future identity decision](2026-09-05-shenyi-future-product-identity.md) continues to own the operator product. The CEM identity here is route-specific customer presentation, not a reversal or rename of internal packages, wire ids, settings namespaces, or the operator shell.

## Alternatives considered

**A separate static application** was rejected because it would duplicate Session transport and could drift from the real streaming behavior. **Replacing the standard root on every pathname** was rejected because it would remove the operator workflow the deployment still needs. **A second server and frontend distribution** was rejected for this delivery because the existing SPA fallback already gives `/customer` an independent URL while sharing the exact authenticated same-origin API. **Reimplementing speech requests in the portal** was rejected because it would bypass the tested browser media lifecycle and drift from the standard call behavior; the voice package instead exposes a client service over the same controllers.

**Keep the conversation provider's default thinking mode.** Rejected because recorded customer turns showed hidden reasoning dominating the wait after retrieval had already completed. This route relies on the approved retrieval and reranking chain for evidence, and explicit non-thinking mode preserves that chain while starting customer-visible answer streaming sooner.

## Consequences

The customer URL has no developer or operations chrome and does not expose a link to `/customer-admin`; operators reach that route directly. Each visit starts from an empty conversation presentation; the customer can reopen or archive earlier customer-service Sessions from the bounded rail, and submitted turns still appear in quality inspection without copying data. Lookup announcements remain inspectable internally but never appear as independent customer bubbles. The route requires an existing Workspace and currently uses the `macau-customer-service` preset. Speech controls require that preset's transcription, realtime, and synthesis profiles. The official logo is a remote CEM asset and requires a local approved copy for offline deployment. Explicit non-thinking response configuration lowers first-visible-answer latency but gives up hidden deliberation for this customer-service route; retrieval and reranking continue to supply the answer evidence. Route-level composition, the fresh greeting state, bounded and filtered history navigation, customer-side deletion, knowledge-backed recommendations, voice controls, prompt delivery, the hidden tool-step announcement, and the absence of operator branding or operations links are covered by client tests and assembled-Web browser evidence.
