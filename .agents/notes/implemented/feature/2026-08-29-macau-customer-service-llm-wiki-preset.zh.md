# Agent Note: Macau customer-service LLM Wiki preset

Status: implemented

[English](2026-08-29-macau-customer-service-llm-wiki-preset.md) | 中文

## Problem

向量 RAG 客服预设通过 embedding 检索和重排选择原始片段。它不提供经人工审核的导航页面、显式页面关系，也没有把每个客服可见引文绑定到精确资料版本与文本区间的批准单元。

如果编译和审核页面与客服会话扫描同一目录，畸形草稿会中断已发布回答，同一段对话也可能跨越多个编译版本。单独的页面状态也不能证明审核人批准了哪些来源字节、规则输入和证据区间。

## Decision

`macau-customer-service-wiki` 是由 `@deepseek-ai/dsh-customer-service-wiki` 支持的独立 Agent 预设。package 包含配置互相独立的两个角色：`WikiCompiler` 拥有可变来源、规则文件、草稿、lint 和发布；`WikiReader` 只拥有不可变已发布 release 和受限客服检索。客服 plugin 不发布编译服务或变更工具。

预设的回复语言由会话作用域的[回复语言选择](2026-08-31-session-response-language-selection.md) plugin 选择并解析。Wiki 指令拥有导航、证据和安全行为，不拥有语言推断。

package 安装带有 `compile`、`lint` 和 `publish` 命令的 `dsh-customer-service-wiki`。编译会规范化来源根目录，拒绝符号链接和 junction，只读取一次每个资料版本，将规范化提取文本划分为精确区间，并在写入前规划全部来源、分段和主题 id。页面 id 采用禁止路径的严格语法；任何 id 或目标路径碰撞都会在草稿变更前失败。编译请求包含完整已规划 id 集，具有完整请求/响应上限，并把来源文本视为不可信数据。`--source-only` 只写导航元数据，不会把来源文本复制到页面正文。

草稿 frontmatter 使用严格 JSON。每个来源引用都携带原始资料 SHA-256、提取文本起止偏移和区间 SHA-256。来源页只授权一个区间；主题页必须包含至少两份不同原始资料的区间。规则哈希绑定 schema、规则和 baseline 输入。Lint 会独立报告畸形草稿，并验证文件名/id 一致、全局唯一、规则版本有效、区间精确、主题资料互异，以及已批准链接指向唯一已批准页面的页面图。

发布是客服可见性的唯一提交点。它拒绝任何 lint 错误，将已批准页面需要的精确原始来源字节复制到 staging release，写入确定性内容寻址 manifest，原子安装不可变 release，并原子替换 `current.json`。客服运行时永远不会扫描草稿目录。预设挂载会在注册提示和工具前验证所选 pointer、manifest 哈希和页面图，因此 release 缺失或损坏会失败，且不会留下部分注册。

地图返回一个 release id，后续每次页面、链接和证据调用都必须重复该 id。页面读取从已复制 release 来源验证全部授权区间；证据使用这些相同的已验证 Buffer，且不能读取已批准区间之外的内容。词法排序只返回正向匹配。证据身份由 release、页面、资料版本、区间和摘录派生，因此 `[page-id:evidence-id]` 在相同调用中保持稳定，也不会仅因两个不同查询都排在第一位而碰撞。

客服提示将页面和摘录视为不可信数据，禁止遵从其中的指令或权限声明，要求事实陈述先取得证据，并在没有支持时如实说明不知道。法律、税务、监管和其他高风险陈述要求证据证明适用日期与范围，并建议用户向主管机关或合资格专业人士确认。

## Alternatives considered

**扩展向量 RAG 预设。** 未采用，因为一个组合会混合检索方法、可变资料根目录、提示词和评测行为。独立预设保留有意义的 RAG 与 Wiki 对比，也防止任一批准模型削弱另一方。

**直接从草稿目录提供已批准 Markdown。** 未采用，因为编辑器的部分保存或无关畸形草稿可能中断全部客服读取，逐项编译也可能暴露混合版本。不可变 release 在发布前完成验证，并为客服工具提供一个 release 身份。

**通过任意一个页面批准整份资料。** 未采用，因为长资料会产生多个独立审核页面。精确区间使批准与引文保持一致；页面不能授权只出现在另一分段中的事实。

**使用调用内局部引文编号。** 未采用，因为同一页面的多次证据调用会分别为不同摘录创建 `[page:1]`。内容派生 evidence id 在持久 transcript 中保持无歧义。

**向客服 Agent 提供编译或批准工具。** 未采用，因为原始资料和编译器输出不受信任，且发布是运维拥有的状态变更。客服会话只接收固定 release 的读取工具。

## Consequences

Wiki 路径要求显式执行编译、审核、lint 和发布，并为每个内容寻址 release 保存一次来源字节。与读取实时 Markdown 相比，这会增加运维工作和磁盘占用，同时获得原子发布、可复现证据、稳定引文、显式部署失败，以及客服流量与草稿维护之间的隔离。

客服会执行地图、页面和证据调用，而不是一次向量查询。它接收没有语义后备的确定性词法结果；零重叠会有意返回无证据。随附澳电 release 将 267 条已选定 FAQ 按业务分类和子分类分组，仅在完整条目边界分成 49 份来源资料，为每份资料批准一个纯来源导航页面，并发布一个链接每个页面的跨资料主题。编译器模型摘要仍为可选操作，并由 package 测试覆盖。

package 测试覆盖配置、Unicode 上限、来源保留与模型编译、完整请求/响应限制、活动取消与超时、递归文本提取、id 规划与碰撞、来源和 release 符号链接拒绝、严格草稿和 release 解析、页面图验证、规则/来源失效、确定性原子发布、已复制来源损坏、release 固定、精确区间证据、稳定 evidence id、零匹配、完整渲染上限、真实 scoped 工具/提示注册和清理、注册前失败的挂载行为、CLI 操作和 invariant companion。聚焦逐文件 coverage 的语句、分支、函数和行均为 100%。无 key 产品 snapshot 会启动随附预设，并固定“地图至页面至证据”的 transcript。
