# Agent Note: 关联证据的会话质量检查

Status: implemented

[English](2026-09-09-conversation-quality-inspection.md) | 中文

## 问题

运营人员需要检查真实会话、理解回答失败的原因，并保存复核决定。虚拟评分或对已变更知识重新检索都无法解释原回答。在客户 agent（智能体）内评分会改变被检查的记录。把缺失的语音数据当作实测质量，会掩盖而非诊断电话故障。

## 决策

现有客服 Host 网关拥有有界检查、异步评估、本地质检记录和修订校验的人工复核。[后台隔离决策](2026-09-04-customer-service-admin-console.md) 继续约束暂存、未接入配置控件和 loopback 访问。会话与质检使用真实记录而不是发音 fixture（测试前置数据）；评估操作不会发布知识或修改语音配置。

检查读取权威实时事件，或通过持久化检查读取记录，不恢复源 Session。内容指纹和完整证据投影固定每次任务的输入。未结束轮次仍可查看，默认评估会跳过；明确选择的未结束轮次拒绝评分。已结束轮次可以独立选择。过大的来源日志明确失败。投影排除内部推理，按记录中的调用标识配对工具输入输出，并保留原始序号与可用耗时。模式脱敏去除常见凭据、电邮和澳门电话号码，但不是完整的敏感数据分类器。

独立 LLM（大型语言模型）请求在没有工具或推理输出的条件下评估选定回合，把有限输出留给结构化 JSON。分发前，准确的系统提示词、消息、输出上限和推理设置会作为事件写入质检目录下的独立审计 Session。客户日志与当前会话选择保持不变。面向运营人员的轨迹标签、错误、推断意图、理由和建议使用繁体中文；引用的客户及证据文字保留来源语言。每次任务存储提供者、模型、规则版本、范围、权重、证据、自动结果和人工复核记录。相同的并行请求会重用执行中的任务。无效输出、不存在的事件引用、超时和遗留任务视为失败，而非零分；重试会产生独立记录。

六个维度覆盖意图、检索相关性、回答依据、处理完整性、表达和执行。除非来源记录了明确路由决策，否则意图属于事后分析。没有标准标注时，检索评估不是准确率或召回率。每个评分维度必须引用原始事件。不适用维度退出分母；证据不足使总分不可用并降低可见覆盖率。严重风险不受平均分掩盖。版本化执行规则按每个已记录错误扣 30 分、每个超过配置阈值的操作扣 10 分，最低零分，不测量未记录的 STT 或 TTS 延迟。

浏览器通过注册的 `operations.trace` slot 使用现有轨迹表，不值导入其他插件的组件。评分引用选择原始记录。人工改分与自动评分分开保留；每项复核或整改状态变更必须包含依据和预期修订号。关闭问题记录的是运营人员验收，而不是已部署真实修复的证明。

## 考虑过的替代方案

**对固定数据评分，或仅在浏览器状态保存结果。** 不采用，因为这些结果无法解释真实客户交互，并且刷新后消失。

**复核时恢复源 agent 或重新检索。** 不采用，因为两者会改变证据或评估不同的语料状态。辅助评估只使用已记录的工具结果。

**只平均模型能够评分的维度。** 不采用，因为高总分可能掩盖检索结果缺失或执行数据未采集。证据覆盖率和不可用总分保留这种区别。

**用独立检查器替换共享轨迹。** 不采用，因为两个事件渲染器容易产生差异。root 作用域 slot 将有界运营投影适配到现有轨迹表。

## 后果

质检消耗独立模型成本和本地磁盘。记录受上限约束，面向单进程并校验修订；没有多用户复核人认证、自动到期删除、批量调度或声学评估。配置评估器的判断仅供参考。严格 JSON 与引用校验可以发现结构错误，不能证明语义结论，仍需人工复核。

## 验证

Host 测试覆盖来源指纹、完整有界投影、评估前请求记录、不修改来源、证据校验、持久化读取、重启恢复、复核修订及整改状态转换。客户端测试覆盖真实历史入口、筛选保留、证据定位、复核依据必填、无效权重和证据不足。组合后的浏览器场景使用确定性的外部模型适配器，经过真实 Remote 网关、冷启动 Session 持久化、质检文件和轨迹 slot，验证评分、证据导航、刷新恢复、人工改分及整改验收。该无密钥场景验证集成，不验证真实提供方的判断质量。
