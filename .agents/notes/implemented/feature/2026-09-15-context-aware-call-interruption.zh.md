# Agent Note: 结合上下文的通话打断

Status: implemented

[English](2026-09-15-context-aware-call-interruption.md) | 中文

## Problem

在 ASR 第一次产生非空临时文字时立即停止播报，会把识别到声音等同于用户想占用话轮。扬声器回授、附近人声及被动附和都可能取消仍有价值的音频和未完成的模型回答。只要求固定打断词又会遗漏列表之外的普通问题及纠正表达。

## Decision

共享浏览器语音控制器只在回答音频实际播报时筛选打断意图。开口信号会建立候选并保持识别，不会停止播报。最终 ASR 话语会立即分类；临时假设必须在部署配置的 `confirmationMs` 内持续保持有效，才可以打断。

分类会综合 ASR 是否最终完成、已持续时间、规范化后的信息长度、字符多样性、提问或纠正句式、完整短附和结构，以及文字与当前回答的相似度。有效话语无需匹配列表短语也能占用话轮。完整的短附和及可能的播报回声会从通话内草稿移除，不进入 Session 历史。确认打断后沿用现有取消、原问题续接及最终片段合并行为。手动打断操作仍立即生效。

Host 在 `call.interruption` 下公布全部随部署变化的时间及阈值：`confirmationMs`、`minimumMeaningfulCharacters`、`echoMinimumCharacters`、`echoSimilarityThreshold` 和 `backchannelMaximumCharacters`。澳电 Web 部署使用 420 毫秒确认时间、三个有效字符、至少六个字符才比较回声、0.82 相似度，以及最多六个字符的短附和范围。

## Alternatives considered

**为每段临时文字请求对话 LLM。** 不采用，因为第二次提供方请求会在打断需要及时响应时增加不稳定延迟，在播报回声期间消耗配额，还要求单独记录模型可见的分类输入。确定性的多信号分类器具有受限的本地延迟及明确的部署控制。

**使用开口或音量阈值。** 不采用，因为无法区分用户有意占用话轮与回声、噪声或附和。

**只使用打断词列表。** 不采用，因为用户会用开放的粤语、中文、英文及葡文表达纠正、问题和话题切换。列出的句式只是一个信号；完整性、持续时间、内容和播报上下文仍可独立影响决定。

**等待所有最终转写。** 不采用，因为用户说出较长纠正时，客服会持续播报到服务端 VAD 结束该话语。稳定且有效的临时文字可在受限的确认间隔后打断。

## Consequences

普通附和与可能的扬声器回声不会再停止正在播报的回答，明确的短纠正和一般有效问题仍可打断。临时文字打断最多增加配置的确认延迟。该分类器不验证说话人，也不是开放式语言模型：具有有效信息的旁人说话仍可能占用话轮，少见的一两个字更正也可能被忽略。单元测试固定时间判断、附和移除、播报相似度、多语言短纠正、续接取消、profile 校验及 Host 公布行为。

此决定部分取代[通话历史与打断后的问题续接](../bug-fix/2026-09-14-call-history-and-continuations.md)中的识别文字打断；其记录保留、原问题续接、合并间隔及持久化 Session 提交仍然有效。
