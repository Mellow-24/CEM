# Agent Note: Macau customer-service knowledge preset

Status: implemented

[English](2026-08-29-macau-customer-service-knowledge-preset.md) | 中文

## Problem

客服对话需要可检索的公司事实、可追溯证据、语言匹配的回答和明确的未知结果。目录成员关系本身不能代表“已批准”：其他 Agent 或进程可以添加文件，来源可能未经审核就发生变化，旧向量缓存也可能保留与批准语料不一致的正文。没有相关性阈值的相似度排序会为普通有限向量始终选出最近片段，即使没有片段支持问题。

若让通用编码预设获得该检索路径，还会为每个 Agent 会话加入无关处理。预设作用域可以隔离该行为，但不会让语料文件自动保密，也不构成租户安全边界。

## Decision

`macau-customer-service` 是一个随附 Agent 预设，包含作用域 persona 和 `@deepseek-ai/dsh-customer-service-knowledge`。该 function plugin 不发布 Cordis service 或模型可见工具。每个包含客户直接文本的候选步骤都会使用最后一条非空客户消息原文检索，并在模型请求前把受限结果附加为持久插件上下文。预设的常驻挂载会在客服会话之间共享私有索引器闭包。其他预设既不会获得自动检索监听器和提示词指令，也不会获得其配置。

预设的语言匹配回答要求由会话作用域的[回复语言选择](2026-08-31-session-response-language-selection.md) plugin 实现。Persona 与检索路径拥有证据和客服行为，不拥有语言推断。

批准由版本 1 来源 manifest 表示。它按路径词法顺序列出每个受支持相对路径，且每个路径只出现一次，并带有批准字节的 SHA-256。预设挂载时会验证真实来源目录和 manifest 文件，拒绝符号链接、无效 UTF-8、不安全路径、缺失或额外的受支持文件及 hash 不一致，然后在接受客户会话前准备向量缓存。来源变化后，只有更新 manifest digest 才能重新使用。缓存缺失或过期时会在启动阶段重建，首条客户问题不再承担语料 Embedding 延迟；准备失败会阻止预设挂载。

磁盘索引是不可信、可丢弃的缓存。复用要求严格解析 JSON，并与当前来源重新派生的路径、标题、标题层级、chunk 正文和内容派生 evidence id 完全一致。其身份还记录 manifest 与批准来源 hash、Embedding 端点与模型、切分参数、解析器版本和向量维度。查询向量维度变化会强制重建；格式错误或过期缓存不会进入模型。缓存路径等于 manifest 或位于来源根目录内时会被拒绝。

每条非空客户问题都会执行 Query Embedding。启用重排时，系统会把有限的向量 Top-K 候选发送给已配置的重排模型，包括最终没有候选能通过向量阈值的情况。重排成功后，证据必须同时通过部署的 `minimumVectorScore` 和 `minimumRerankScore`。没有片段保留时返回 `not-found` 和 `insufficient-evidence`；空批准 manifest 返回 `empty-corpus`。瞬时重排失败时，当前查询只回退到通过向量阈值的候选，并会在之后重试。调用方取消会继续传播，不改变后续行为。

随附组合使用 DashScope `qwen3.7-text-embedding` 和 `qwen3-rerank`，并启用重排。其 `minimumVectorScore` 为 `0.45`，可在部署模型中区分已审核澳电正例与已移除的澳门工业税问题。

一个 FIFO 队列会在共享常驻实例的所有会话之间串行执行验证、缓存发布和搜索。查询、摘录和完整结果限制均使用 UTF-8 字节。完整规范 JSON 和模型渲染文本必须分别满足 `maxResultBytes`；在发出超限结果前先缩短摘录，再丢弃来源。

每个内部结果都带有内容派生 evidence id，但模型可见 renderer 只输出摘录正文，并把来源控制的 markup 转义进 JSON 数据块。常驻提示词和结果文本都明确规定来源字符串是引用数据而非指令，并禁止向客户暴露文档、标识、分数或检索过程。插件把精确查询、受限证据、结果状态、是否重排、来源数量和耗时记录在 `customer-service-knowledge/retrieval` 中；质检投影会把该事件显示为自动知识检索 trace。

## Alternatives considered

**把一个目录内所有受支持文件视为已批准。** 未采用，因为未审核文件或同大小修改会静默成为模型证据。Manifest 把批准变成可审核的精确字节决定，并拒绝目录清单漂移。

**来源大小和修改时间一致时信任缓存。** 未采用，因为时间戳无法证明内容、配置、chunk 派生或向量空间身份。只有当前批准字节能独立重现全部非向量字段时，缓存才可节省 Embedding 工作。

**宿主范围的知识服务。** 未采用，因为每个在线 Agent 都可能解析一个共享能力，而 service API 只有一个内部消费者。私有闭包已经提供需要的常驻生命周期，无需扩大宿主 service 注册表。

**第三方 MCP 记忆服务。** 未采用，因为 MCP 工具目录不能提供所需的批准 manifest、缓存校验、相关性阈值、稳定证据引文或完整结果限制。MCP 记忆仍适合可选个人记忆，不适合已批准公司证据。

**让模型先调用检索工具再回答。** 未采用，因为该客服预设会在 Embedding、重排和回答请求之前串行执行一次完整模型请求。自动检索保留相同候选阈值与重排器，同时移除前置请求；代价是检索使用客户消息原文，而不是模型改写后的查询。

**为降低延迟而停用或绕过重排。** 未采用，因为精确 FAQ 表述和含糊的自由提问都必须经过部署的向量检索路径。每条非空问题都会保留 Query Embedding、向量阈值和已配置的重排。

## Consequences

来源根目录和 manifest 必须在预设挂载前存在。批准语料或索引身份变化而需要重建缓存时，挂载过程可能联系 Embedding 端点并延后服务就绪。每条客户直接消息都会在唯一一次回答请求前执行 Query Embedding 和重排，来源向量重建则留在客户回合之外。搜索会在重新校验来源字节和派生 chunk 后复用已准备缓存。运维人员必须针对所选模型，使用已批准正例与域外问题校准两个相关性阈值。

Embedding 端点以及启用时的重排端点会收到批准片段和客户查询，因此属于部署的数据可信决定。预设会把自动检索排除在其他 Agent 组合之外，但语料和缓存的机密性仍取决于文件系统位置及政策。仓库随附的澳电语料为每条已发布 FAQ 选择一个按来源优先级决定的答案，保留适用条件和来源版本，并排除同一优先级仍冲突的条目、动态缴费二维码占位符、陈旧燃油价格比较，以及声称客户当前供电状态的回复。

来自表格的 FAQ 增量采用答案精确去重：已批准中文答案留在现有权威条目中，新增英文和葡文答案则使用带稳定 FAQ id 与来源行号的单语言 section。这样既避免重复中文片段占用有限的检索结果名额，又保留供 Embedding 直接处理的多语言问题文本。

当前来源格式仍以文本为主。PDF、DOCX、图片、音频和表格感知抽取必须先具备已批准解析器及来源政策，才能加入 manifest 格式。

## Verification

聚焦包测试固定了 manifest 拒绝路径、严格缓存复用与投毒拒绝、向量维度变化、精确 FAQ 标题问题的完整检索、两个相关性阈值、取消与瞬时重排重试、共享实例串行化、UTF-8 查询/结果限制、自动上下文注入与清理、持久检索关系和质检 trace 投影。随附预设组合提供全部必需运行值，并为仓库内来源提供精确 manifest。无密钥的 Web 装配快照以一个模型步骤到达客户回答，包含英文及葡文 FAQ 证据，并验证面向客户的答案不会显示 evidence id。
