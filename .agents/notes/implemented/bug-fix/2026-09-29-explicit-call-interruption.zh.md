# Agent Note: 明确意图的通话打断

Status: implemented

[English](2026-09-29-explicit-call-interruption.md) | 中文

## Problem

转写文字长度和一般问句无法证明用户想停止客服回答。生成期间的附和会绕过仅在播放时启用的筛选，普通旁人聊天也会达到三个字符的门槛，从而取消仍有价值的回答。

## Decision

可选的[混合式通话打断](../feature/2026-09-30-hybrid-call-interruption.md)取代纯规则接纳并增加单字过滤；本记录保留取消归属及保守筛选的依据。

通话控制器在本次回答的完整生命周期内筛选输入，包括生成和合成准备。候选是否开始于回答期间会被记录，并持续筛选至最终识别，即使播放先结束。未接纳的临时文字不能改变显示状态、加入会话消息或取消合成。静音会清除待确认的打断证据。

只有明确停止命令，或最终识别且指向客服的纠正和澄清句式可以占用话轮。临时停止命令从识别到文字起等待配置的确认间隔；其他定向请求必须等待最终转写。意图判断前先检查短文字的完全回声匹配和较长文字的相似回声，包括引用的停止命令。文字长度和任意问句不能独立授权取消。单独的停止命令清空排队问题并保持收听，不增加模型请求；复合命令保留后续问题。没有活动回答的收听状态仍通过现有语句合并间隔接纳普通提问。

此决定部分取代[结合上下文的通话打断](../feature/2026-09-15-context-aware-call-interruption.md)中的接纳条件及仅在播放时启用的范围。其本地筛选、取消、手动打断及原问题续接机制继续保留。ASR、回答语言选择、检索和 TTS 提供方沿用现有配置。

## Alternatives considered

**只增加确认时间。** 较长的背景聊天仍会通过长度规则，最终识别也会绕过临时文字延时。延迟所有识别还会拖慢普通提问，却无法确定意图。

**增加模型请求或声纹登记。** 模型请求增加提供方延迟，而且无法通过文字识别说话人。声纹登记需要音频身份依据和独立产品流程，当前转写流不提供这些能力。保守接纳在现有延迟预算内处理意外打断。

**将所有识别问句视为插话。** 这样可以接纳自然的话题切换，但也会接纳附近的聊天。回答期间要求明确停止、纠正或指向客服的句式；收听期间仍可提出普通新问题。

## Consequences

附和、不含命令的噪声及普通背景聊天不会停止回答，也不会进入待提交问题。没有称呼或明确指向的新问题可能无法打断；用户可说出明确停止命令，或等待收听状态。没有说话人验证时，旁人说出同样被接纳的命令仍无法区分。提供方误识别和声学环境仍需实际麦克风测试。

分类器和控制器回归覆盖附和、背景问句、明确命令、定向纠正、短回声、生成期间输入、取消及延迟最终事件。完整浏览器回放验证忽略语音时继续播放且历史不变，随后可以接纳明确打断。不增加模型或语音提供方请求。
