# Agent Note: 保护固定通话欢迎语免受声学误打断

Status: implemented

[English](2026-09-07-protected-call-greeting.md) | 中文

## Problem

识别服务的开口事件无法区分用户和扬声器回声。首次开口事件就停止固定欢迎语，可能使完整音频在前几个字后被截断。

## Decision

通话播放欢迎语时并行准备识别服务和麦克风采集，但在欢迎语自然结束前于本地丢弃麦克风帧。开场期间忽略识别服务的开口和转写事件。提供方错误和挂断仍会终止播放并释放采集。欢迎语结束后恢复正常识别、转写提交和回答打断，不增加额外定时等待。

这只替代[语音通话设计](../feature/2026-09-03-customer-service-voice-calls.md) 中欢迎语的打断行为；其会话所有权、传输上限和持久化文字决策仍然有效。

## Alternatives considered

**欢迎语期间信任开口或临时文字。** 两者都不能证明音频来自用户而非扬声器。匹配欢迎语文字还可能过滤用户真实的简短问候。

**禁止打断所有回答。** 否决，因为用户需要打断较长的生成回答；保护区间仅限于简短固定开场。

## Consequences

用户须等待欢迎语结束后提问；开场期间的语音不会缓存或转写。不增加模型请求、持久化事件或提供方凭据。控制器测试覆盖开口、临时／最终回声转写、音频抑制、欢迎语后上传、挂断与提供方错误。两个客服预设的浏览器回放验证预加载欢迎语在注入识别事件后仍自然播完，随后接纳提问。开场后的声学表现仍依赖播放设备与环境。
