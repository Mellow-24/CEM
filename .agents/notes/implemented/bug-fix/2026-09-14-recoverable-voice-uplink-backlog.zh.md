# Agent Note: 从短暂语音上行阻塞中恢复

Status: implemented

[English](2026-09-14-recoverable-voice-uplink-backlog.md) | 中文

## Problem

浏览器将单次麦克风上传的 64,000 字节上限同时用作全部排队与在途 PCM 的上限，这一容量只相当于两秒音频。因此，单次请求变慢或浏览器主线程暂停，就可能在识别已经成功后结束原本健康的通话。

## Decision

浏览器将单次请求的传输上限与上行总积压分开。每个有序请求仍最多包含二十个完整的 100 毫秒 PCM 帧，即 64,000 字节。在途请求期间采集的帧按先进先出顺序保留，并按需拆分为多个符合限制的请求。

Host 将 `call.maxPendingAudioMs` 作为必填部署设置公布，范围为 2,000 至 60,000 毫秒，增量为 100 毫秒。浏览器按这个时长统计排队与在途 PCM，只有合计音频超过上限才结束通话。澳门 Web 部署使用 8,000 毫秒，最多保留 256,000 字节原始 PCM，同时允许短暂请求或调度阻塞自行排空。恢复期间不会丢弃音频或改变顺序。

## Alternatives considered

**增加单次请求的 64,000 字节上限。** 否决，因为 Host 路由与 Qwen 提供方分帧有意限制单次请求。更大的浏览器请求会被拒绝，或产生过大的提供方写入。

**移除总积压上限。** 否决，因为断开或永久阻塞的上传会无限保留音频，并可能在恢复后重放过期问题。

**保留两秒的合计上限。** 否决，因为即使提供方连接仍然健康，它也会将普通的短暂调度与传输延迟视为终止连接的错误。

## Consequences

短暂上行阻塞可能使识别延后相应的积压时间，但不再强制重新接通。持续阻塞仍会在配置的上限结束通话。客户端测试会在四十帧到达期间阻塞第一次上传，随后验证通过符合传输上限的分批请求完整有序地发送；另一个上传阻塞测试验证八秒总上限。Host 与客户端 profile 测试拒绝无效时长，并验证解析后的设置到达浏览器。
