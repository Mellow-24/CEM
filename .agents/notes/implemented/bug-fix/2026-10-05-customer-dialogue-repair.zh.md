# Agent Note: 客户纠正与按需称呼

Status: implemented

[English](2026-10-05-customer-dialogue-repair.md) | 中文

## Problem

客户要求客服称呼自己，不需要公司政策依据。将无依据拒答套用到这类请求，会掩盖真正的对话意图。每次纠正都在前面拼接被打断的原问题，也会让检索把被否定的前提视为当前输入。即使客户已经否定，历史业务答案仍可能主导对话。

## Decision

[知识库指令](../../../../packages/preset/customer-service-knowledge/src/evidence.ts)要求业务事实依赖相关已审核依据，同时允许依据客户原话和当前会话进行对话互动。没有检索依据，不妨碍确认、道歉、纠正或回应称呼要求；仍禁止虚构公司事实、无依据的账户访问和已经完成操作的说法。客户纠正不能覆盖安全、授权、证据或回答语言规则。

当前检索依据紧接在最新客户直接消息之前入日志。提供方收到的两条消息均使用 user 角色，不带内部插件来源标签；将客户原话放在依据之后，可以区分客户要求的动作与依据提示。包括运行时上下文在内的其他消息保持原有相对顺序。每条非空客户问题仍按未改写的原文执行 embedding 和 rerank。

[澳电角色提示词](../../../../apps/cli/config/agent-presets/macau-customer-service/agent.cordis.yml)优先处理客户最新的真实诉求，而不是被否定的话题和答案。明确提供的姓名和偏好称谓仅属于当前会话，后续纠正优先。客服不猜姓名或带性别的称谓，不主动收集姓名，也不把姓名当作提供服务的前提。仅当客户要求个性化称呼、却没有提供可用偏好时，才可以询问如何称呼。

[语音控制器](../../../../packages/client/ui-voice/src/client/call.ts)在打断后只提交新接纳的话语。同一句话内的最终 ASR 片段仍按顺序合并，包括取消期间排队的片段。历史问题继续作为独立持久化消息，为回答模型和打断分类器提供上下文。此决定取代[通话历史与续接](2026-09-14-call-history-and-continuations.md)中的跨轮问题前缀，不取代记录保留、合句时间或取消归属。[混合式打断接纳](../feature/2026-09-30-hybrid-call-interruption.md)保持不变。

## Alternatives considered

**增加串行意图分类器或答案校验器。** 普通回答会多一次提供方往返。现有回答请求已经包含当前问题和会话，策略区分应在该请求中完成。

**对疑似社交文字跳过 embedding 或 rerank。** 关键词捷径可能误判混合请求，并绕过已审核业务依据。每条非空消息仍执行检索，由回答指令区分证据约束的对象。

**始终询问姓名。** 这会打断只想办理业务的客户，并收集不必要的个人信息。个性化称呼由客户发起。

**每次打断都携带完整旧问题。** 这可能帮助理解孤立片段，但也会累积被否定的前提。分开记录轮次可以保留上下文，而不把旧文字放进每次新检索的问题中。

## Consequences

此改动不增加提供方调用、生成后缓冲、模型切换或持久化客户档案。Embedding、rerank、ASR、TTS 路由及降级、回答语言选择保留原配置。新增提示词会影响模型输入长度，首字时间仍取决于提供方。如果当前依据和对话无法解释过短的追问，可能需要聚焦澄清。

控制器定向测试覆盖重复纠正与同句话合并。已发布预设的无密钥 transcript（文本记录）固定业务依据和无依据对话轮次。按凭据启用的真实提供方测试验证纠正、按需称呼和英文切换；浏览器回放覆盖新客服和手机端共享通话入口。这些检查不能证明说话人身份，也不能保证每一次生成式回答。
