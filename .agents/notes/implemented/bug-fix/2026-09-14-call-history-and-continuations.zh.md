# Agent Note: 通话历史与打断后的问题续接

Status: implemented

[English](2026-09-14-call-history-and-continuations.md) | 中文

## Problem

仅显示最新一组问答的通话界面，会在识别更新当前字符串时移除开场白及此前交流。短暂停顿还可能提前提交未说完的问题；打断其回答后只提交补充短语，即使持久化历史仍在，也增加了还原完整问题的难度。

## Decision

共享语音控制器保留通话内的临时文字记录，为欢迎语、用户话语及按轮次和步骤区分的回答提供稳定条目。临时 ASR 更新同一草稿，提交完整片段后结束该草稿。生成回答直接从 Session 投影更新，不依赖 TTS；生成或播放被取消后，文字保留并标记为已打断。静音或放弃的草稿保留并标记为未提交。开始新通话时重置这份展示记录，欢迎语与未提交草稿不会成为模型历史。

澳电手机界面直接呈现记录，不添加外围卡片。默认跟随最新文字，允许不显示滚动条轨道的历史回看；更新及收起通话时保留阅读位置，并提供明确的返回最新内容操作。

自动打断等待非空临时或最终 ASR 文字。只有开口信号而没有文字时，仅延后已有最终片段的提交截止时间。Web 部署将最终片段合并间隔设为 850 毫秒，以额外 700 毫秒等待减少过早交接。加上提供方的 250 毫秒静音窗口，正常交接约需 1.1 秒，尚不包含传输及生成耗时。

识别到续说或用户明确点击打断，取消当前回答时，下一条提示包含该回答对应的原问题及后续所有最终补充片段。取消达到空闲后才提交，其间到达的补充按顺序合并。新文字通过普通 Session 提交流程记录，不修改旧消息。回答及播报全部结束后，下一问题不再重复前一个问题。切换话题和更正由现有模型理解，客户端不另设分类器。

## Alternatives considered

**仅保留最新一组问答，挂断后再看聊天。** 不采用，因为用户需要在继续通话的同时回看之前交流。

**禁用打断。** 不采用，因为真正的更正需要停止未完成回答；识别文字比单纯开口信号提供更多依据，且无需新增提供方。

**改写或删除前一条用户消息。** 不采用，因为这会改变持久化历史，并掩盖被打断回答收到的实际输入。续说内容明确出现在下一条已记录提示中。

## Consequences

续说提示会重复原问题文字，因此增加输入 token。临时通话历史不是录音，也不替代持久化 Session。非空 ASR 不等于说话人验证，背景人声与识别幻觉仍可能打断；仍需实机验收。

单元测试覆盖无文字开口、打断后的问题续接、取消期间累积、回答结束后的新问题分离、记录保留及手动回看。组装后的无密钥澳电浏览器场景验证 350 毫秒停顿、合并提示入日志、保留打断文字、回看开场白、连续音频、响应式布局及持久聊天。此决定部分取代[客服通话设计](../feature/2026-09-03-customer-service-voice-calls.md)的仅开口即打断及短交接间隔，原有授权与生命周期规则仍有效。[回复可见及降级设计](2026-09-14-visible-call-replies-and-tts-fallback.md)继续负责音频失败处理。

[结合上下文的打断设计](../feature/2026-09-15-context-aware-call-interruption.md)取代所有非空临时或最终文字均打断的行为。记录保留、原问题续接、合并间隔及持久化提交仍然有效。
