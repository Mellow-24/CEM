# Agent Note: CEM 基于公网 IP 的认证部署

Status: implemented

[English](2026-09-15-cem-authenticated-ip-deployment.md) | 中文

## Problem

CEM 客服门户需要在尚无域名时提供公网演示。裸 HTTP IP 无法提供浏览器采集麦克风所需的安全上下文，而在没有访问控制时发布共用 Session 与运营管理 API，会暴露客户对话及运营功能。

## Decision

北京演示实例让应用继续监听 `127.0.0.1:3080`，仅通过 Nginx 对外提供服务。Nginx 对全站进行身份验证，将根路径重定向到 `/customer`，以无缓冲方式代理流式连接和升级连接，并为服务器公网 IP 终止受公共信任的短周期证书。

部署 overlay 将 `speech-web.authority` 设置为 `trusted-host`，服务通过 `--trusted-host` 传入公网 IP。这两项设置只在 Nginx 身份验证之后授权浏览器来源，不会把主机白名单当成用户身份验证。运行凭据保存在仅 root 可读的服务器环境文件中，Session、知识库、质检、发音规则和检索索引状态保存在 `dsh` 服务账户的持久化数据目录中。

IP 证书使用 ACME 短周期 profile，并每天自动续期多次。后续改用域名部署时，会同时替换 Nginx 证书和可信来源，而不会长期并行提供两套身份。

## Alternatives considered

**直接暴露 3080 端口。** 不采用，因为 Web 启动器有意仅监听本机，直接使用 HTTP 不能启用浏览器麦克风，而且会绕过反向代理提供的身份验证和传输控制。

**使用自签名证书。** 不采用，因为每个客户端都需要安装私有信任，浏览器麦克风行为也会依赖这项手工配置。

**等待备案域名。** 不采用，因为受公共信任的 IP 证书能够为演示实例提供所需的安全上下文，无需把域名或 ICP 备案作为前置条件。域名仍是长期公网身份的首选。

## Consequences

客服门户、语音输入、电话界面、共用 API 和运营管理页面使用同一个经过身份验证的 HTTPS 来源。演示用户访问时会看到 HTTP Basic 身份验证提示。有效期六天的 IP 证书依赖可靠的自动续期；公网 IP 发生变化时，需要重新签发证书并更新 trusted-host。该配置不提供逐客户身份或租户隔离，因此仍是受控演示部署，而不是匿名公共服务。
