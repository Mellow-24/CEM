# Agent Note: 独立的移动 Web 入口

Status: implemented

[English](2026-09-11-independent-mobile-web-entry.md) | 中文

## 问题

现有浏览器应用是面向桌面的工作台。移动端需要为文字、麦克风和通话提供不同的交互模型，但直接修改已组装的桌面 Shell 会扩大现有 Web UI 的回归范围。

## 决策

Web 前端构建两个 HTML 文档，均加载 `AppWebEntry` 并接收 Host 启动 manifest（元数据清单）。`index.html` 选择桌面 AppFrame；`mobile.html` 声明 `data-dsh-mobile`，在同一布局插件中选择 MobileFrame。移动端外壳通过现有的对话、侧边栏、详情和覆盖层 slot，每次显示一个面板。两个文档共享客户端插件组装、会话服务、agent（智能体）预设、模型选择、工具、审批及已配置的语音提供方。不另设移动端消息存储或 agent 传输通道。

MobileFrame 在导航时保持面板挂载，选择会话后返回对话，并根据可视 viewport 调整尺寸以适应键盘变化。对话所属的 CSS 通过显式文档标记限定移动样式，包括可换行的输入栏控件和移动端 hero。移动启动文档与桌面入口一样经过 index 转换器；无关 HTML 资产不会接收可执行的启动配置。

移动端语音平台通过页面的同源凭据通道获取欢迎语、通话句子和已提交消息的音频，每个运行时通过一个媒体元素播放本地 Blob URL。原生媒体加载可能在页面认证请求成功时单独失败，而解锁某个元素的手势未必授权之后新建的元素。因此，后续句子及回答始终复用同一个已解锁元素。解锁用的静音不发布通话事件。每次准备操作拥有各自下载及 Blob URL，只有当前播放的准备操作才能清除共享媒体源。桌面播放保留直接 URL 的渐进式加载。

## 曾考虑的替代方案

**让现有桌面 Shell 响应式适配。** 不予采纳：响应式布局不能提供独立的移动交互模型，也会让移动端迭代绑定到桌面端回归范围。

**创建第二套客户端插件组装，或从移动页面直接调用模型。** 不予采纳：两种方式都会重复会话归属、工具执行、权限处理和语音生命周期。不同的展示方式不需要第二套 agent 运行时。

**取消欢迎语路由认证或禁用证书校验。** 不予采纳：修复媒体兼容性不意味着可以降低部署访问控制。通过页面认证信息加载音频会保留现有服务端校验，并分别报告 HTTP、下载和播放失败。

## 后果

构建后的前端同时暴露 `/mobile.html` 和 `/`，不改变桌面入口选择。agent 能力和语音可用性由选中的 Host 预设决定。通话使用现有浏览器语音对话，不拨打电话号码。浏览器测试覆盖组装后移动应用的流式回复、工具结果、持久化历史、会话选择、agent 选择、取消及语音通话挂断；外壳测试覆盖面板生命周期和键盘几何变化。

提供移动文档不会改变网络信任设置：服务仍默认仅监听回环地址。实体手机需要显式配置的安全网络通路才能连接 Host；麦克风访问还需要浏览器信任的安全上下文。发布未经认证的 agent 端点不属于此次展示改造。

移动播放测试覆盖提前点击、播放源复用、互不干扰的预读取消、延迟播放拒绝、HTTP 错误、无效响应、媒体错误及 Blob 清理。组装后的浏览器回放拒绝原生媒体欢迎语请求，但允许页面 fetch；它记录 403 失败快照，并验证重新接通。CEM 回放在欢迎语之后拒绝新建媒体元素播放，并要求后续回答在已解锁元素上连续出声。移动端每句音频需完整下载后播放，响应大小受 Host 限制，因此可能增加起播延迟；下一句预读与当前播放重叠。字幕投影和提供方降级仍由[通话回复及降级决策](../bug-fix/2026-09-14-visible-call-replies-and-tts-fallback.md)分别负责。厂商手机播放器仍需实机验证；这些检查不声称所有媒体错误 4 都有同一原因。
